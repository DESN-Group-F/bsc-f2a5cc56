## Included scope

- Teaching groups separates default membership from ongoing actual checkouts. Staff may explicitly continue an existing loan, add uncovered members, exchange batteries with reviewed return responsibility, deliberately start another session, or permanently replace one default member. Append-only migration `0022_teaching_checkout_changes.sql` retains original run evidence, exact loans and guarded change history. See the [teaching checkout guide](../teaching-checkout-alternatives.md).
- The sign-in page has staggered entrance and button/status motion, explicit English field validation, password-manager support and recoverable access checks. Shared loading feedback uses a battery motif and skeleton shimmer; existing records stay mounted during refresh. Slow requests receive descriptive feedback and bounded read failures. Reduced-motion preferences suppress animation. No fake completion percentage or automatic write retry is introduced.
- Mapping is available to both staff and administrators from the primary sidebar. Overview contains a schematic isometric canvas with three default J18 placeholder rooms and Unknown. Other reference buildings remain disabled. Hover/focus outlines, selection enlargement, background room shrink/blur, summary transitions and reduced-motion support use the existing visual system.
- Selecting a room opens its summary. View details opens or focuses an independently closable room tab. Tabs retain their own filters, page and selections; Overview retains its building Filter. The existing table supplies battery details, reviewed movements, retirement, teaching groups and complete downloads with the same permissions.
- Every map count describes the latest saved observation, with time and source available in the room summary and battery history. It does not confirm present physical location. Registered home, responsible ownership and active loans stay separate. Unknown does not discard observations outside this map. Retired assets remain outside default counts.
- Existing observation storage, latest projection, query model and exports are extended together. Fixed room boundaries apply even to selected and single-record downloads. Saved observation labels survive directory renames, and older uploads do not supersede later observations.
- Administrator location setup maps beacons to existing rooms. An explicit single-battery simulator records demonstration evidence through the server; empty or conflicting room evidence is audited without replacing the last definite observation. Staff may view the directory. Working-inventory mappings require verified rooms, and hardware ingestion is disabled.
- Migration `0021_location_beacons.sql` adds one configuration table and guards. Existing observations, audit events and exact-request receipts are reused. Interrupted browser requests retain the original payload and can be retried without duplication. No new registered-home task is added for staff.

## Validation and limits

The isolated formal web source passed **827/827 tests**, zero failed/cancelled/skipped, in 234.27 seconds; **224/224 isolated HTTP checks** using all twenty-three migrations; TypeScript; full ESLint; and the production build. The build excludes the diagnostic NFC route. These are tests of the exact application source in the publication snapshot; subsequent edits only record the validation and publication boundary. The earlier 867-test development run and final 25-case display-label regression remain separate historical evidence. Prototype-only tests are absent from the formal snapshot.

Independent review checked all 519 source files, exact source hashes, previous migration bytes, dependency preservation, shared protocol and license retention, neutral reachable history, relative documentation file links and high-confidence secret patterns. The new source tree adds 26 files and modifies 67 relative to 0.9.0, with no removals. Such pattern scans cannot prove that every possible credential format is absent.

Actual integrated results are recorded in the [validation record](../validation.md), including the Teaching lifecycle, sign-in, slow-network and earlier Mapping browser checks. The [mapping guide](../mapping-and-location-observations.md) documents the location server contract, recovery workflow and evidence boundaries.

Hardware models, Bluetooth broadcasts, native phone scanning, room confidence and physical acceptance remain future work. The drawing is a schematic, not a surveyed floor plan. Browser tabs retain state during the current account/dataset session; they are not promised to survive a page reload. There is no live location feed, and simulated observations remain labelled as simulation.

The source snapshot has the 0.9.0 commit as its sole parent and uses `admin <admin@inventory.local>` for author, committer and tagger. Publication adds only the version branch and annotated tag, without replacing existing references. The development checkout, local preview data, team main branch, mobile test branch and earlier release references remain separate.

Existing migrations 0000 through 0020 retain their exact frozen bytes. Dependency declarations, package scripts and the complete resolved lock graph are unchanged except for the three root version fields. Native/mobile source, the diagnostic NFC route, prototype-only tools and guides, local credentials, sessions, business databases, installed dependencies and generated builds are excluded. Shared Teaching NFC and operator-entered registration contracts required by the web application remain. `.openai/hosting.json` and authentication adapter protocol identifiers retain their functional provider-required names; these are hosting/authentication contracts rather than product branding. Required third-party licenses are preserved.
