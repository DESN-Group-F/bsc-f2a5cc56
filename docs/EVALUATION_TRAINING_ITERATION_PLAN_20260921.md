# BSC 项目测试与训练迭代方案

日期：2026年9月21日  
状态：讨论稿，尚未执行（PROPOSED_NOT_EXECUTED）  
适用范围：Qwen、资料检索、案例状态与数据库、物理化学及工程分析工具。  
目的：用测试决定改哪里、是否值得训练，并验证改进是否能推广到未用于调试的案例。

建议采用“持续评测、按问题选择改进、达标才保留”的循环。评测贯穿每轮，训练按证据触发；一轮可以只修数据、检索、工具或提示。未经本项目微调的模型始终保留为对照和回退版本。

整体顺序：确定任务与判分 → 建立基线 → 分析失败 → 系统修复或专项训练 → 验证和回归 → 保留、回退或结束。只有达到预定条件的候选版本才进入独立验收。

## 1. 当前起点与本轮范围

现有数据准备成果可以支持编制情景和证据包；扩大的锂电型号覆盖、部分运行条件和现场输入仍有缺口。已完成的数据整理检查，不等于模型或系统的效果测试。

继续采用“通用分析＋当次产品和现场资料”的产品路线。首轮明确支持哪些任务，公开记录其他任务的覆盖缺口；不把手头资料方便处理的部分默认为全部测试范围，也不把所有商品型号均已收齐作为首轮启动条件。

本文件只提出设计与决策规则。未读取旧模型测试题或答案，未生成训练样本，未运行Qwen、正式检索、目标数据库、模型评测或训练。历史初测保持用户报告及既有证据的原状态，不补写成绩。实际执行继续遵守项目服务器边界。

## 2. 分阶段推进

| 阶段 | 工作内容 | 可审查的交付物 | 进入下一步的条件 |
|---|---|---|---|
| P0 定范围 | 以产品任务建立覆盖表，定义输入、预期表现和严重错误 | 测试范围表、判分卡、指标及数据用途清单 | 每个首轮必测任务都有可判定的标准；其余明确为未覆盖或待补依据 |
| P1 校准测试 | 用少量跨类型案例检查题目、参考计算、评分与运行记录 | 评分分歧记录、修订后的判分规则 | 可以稳定区分正确、错误、合理未知和不可判分；此步不宣告模型达标 |
| P2 建立基线 | 在服务器核验实际模型和组件，完成组件检查及B0至B3对照 | 可复现的基线、原始输出与失败记录 | 核心工具、评分器和测试流程可信，主要失败有证据可追踪 |
| P3 按失败改进 | 优先修复资料、解析、检索、工具、状态或提示问题 | 单轮改动说明和配对对比 | 改动有收益且没有超出预定容差的退化，才保留该版本 |
| P4 条件性训练 | 对持续模型行为缺陷建立审核过的训练候选，进行有预算限制的实验 | 训练决策、独立数据划分、候选模型及验证报告 | 满足训练触发条件；用相同外围系统比较，收益足以支持采用 |
| P5 独立验收 | 冻结选定候选，使用未参与调参的封存案例验收 | 分任务结果、严重错误、成本及支持范围 | 满足事先登记的验收标准；未通过则保留失败和原因 |

P3和P4可以多轮往返。每轮都验证，P4可以完全跳过。最终验收不承担日常调参功能。

## 3. 首轮覆盖怎样确定

以“任务 × 输入条件 × 产品/场景层级”组织案例，不机械生成所有组合。每个首轮必测任务都应有正常可完成案例和有代表性的边界案例。标明已设计、已审查、已执行、待补依据和暂未覆盖，避免只公布一个总体分数。

| 任务 | 正常能力 | 必须检查的边界 |
|---|---|---|
| 科学与工程解释 | 正确解释关系、提出有依据的分析 | 把相关性当因果；将局部计算外推为温度、事故概率或寿命结论 |
| 产品资料理解 | 匹配型号、版本、单位、脚注和条件 | 相近型号混用；试验条件误当运行限值；家族资料误当精确型号规格 |
| 检索及证据引用 | 查到适用证据并正确引用 | 有关但不适用；没有直接案例；检索服务故障；资料冲突或过期 |
| 数值及实验数据分析 | 正确选方法、使用工具、解释结果 | 单位错误、符号约定不明、缺采样、异常值、工具超时或失败 |
| 状态判断与补充核验 | 区分已知、推断和未知，提出能区分候选原因的核验 | 信息不足仍确定唯一原因；无依据生成概率；把未知当正常 |
| 建议和升级路径 | 给出有条件、可追溯的建议 | 外校流程冒充UNSW程序；现场条件缺失；普通解释被不必要拒绝 |
| 多轮及案例状态 | 用新增测量、修正型号和历史记录更新判断 | 继续沿用已纠正数据；陈旧记录当实时测量；用户转述当直接采集 |
| 系统完整性 | 真实记录执行结果，按任务权限使用信息 | 虚构执行或批准；外部资料中的指令干扰任务；跨案例信息泄漏 |

优先覆盖锂电池场景；化学体系、圆柱/方形/软包、电芯/模组/电池包/系统、实验室/便携设备/工具/储能分别保留覆盖标签。轻型交通等缺完整产品资料的场景，区分“缺证据时的正确处理”和“已具备足够资料的完整任务”，不混成同一种通过率。

首版题量由覆盖需求、判分成本和结果不确定性确定，与112 GB文件体积无直接关系。先校准评分流程，再确定正式样本量和分层数量，不预定固定万级题库或训练集。

## 4. 数据分工及测试污染控制

| 数据用途 | 允许做什么 | 不能混淆的用途 |
|---|---|---|
| 开发与诊断案例 | 查看失败、修改提示和系统、研究错误原因 | 不能宣称为完全未见的验收成绩 |
| 训练集 | 未来在用途获准后，更新模型参数 | 不能从封存验收题或答案直接派生；运行日志不自动成为训练数据 |
| 内部验证集 | 选择训练轮次、参数和候选版本 | 反复选模型会适应该集合，结果只作开发证据 |
| 回归集 | 检查已解决问题及原有能力是否退化 | 通过旧题不能单独证明新案例泛化 |
| 独立封存验收集 | 评价冻结后的最终候选 | 开发者和训练过程不可接触答案；不逐轮用于选版本 |

数据划分先于训练样本扩增。以原始来源、同一实验/电芯、案例及其派生关系分组；需要证明未见型号泛化时，进一步按型号或家族划分。检查直接重复、相邻数据片段、近重复改写、引用链和文件名/元数据中的答案提示。合成改写保留父案例标识，不能靠改写绕开分组。

用于检索能力测试的合法原始参考资料可以在规定的知识库中；标准答案、评分要点、评语和诊断用答案提示必须隔离。RAG允许阅读参考资料与模型提前见过验收答案是两个不同问题。

开发失败可在审核、许可和重新分类后成为训练来源，但原案例及其近似变体从此不能作为独立泛化证明。一批验收结果一旦被用于指导改进，该批即不再作为完全独立的验收依据，可保留作回归；下一次验收需有新的独立封存批次，并记录查看次数。

无法仅凭测试证明底模预训练从未见过公开材料。以来源记录、任务构造、受控条件变体及分组保留降低污染风险，保留这一限制，不把“未用于本项目训练”写成“底模绝对未见”。

## 5. 基线与每轮比较

先单独检查解析、检索、单位换算、数值工具、状态更新和评分器，参考数值由独立方法产生。待测工具不能同时生成自己的标准答案。已知正确、已知错误和合理未知的输出用于校准判分。

模型基线保留四种配置：B0为未经本项目微调的Qwen与题内信息；B1加入RAG；B2加入分析工具；B3加入完整案例状态和运行流程。比较同一批适用案例，固定模型、量化、提示版本、资料/索引、工具、预算与有效推理设置；各配置新增能力及实际总成本单独报告。需要外部资料的B0案例按其可见信息评价，正确说明缺失不算失败。

D_ORACLE是开发阶段的证据诊断：把经过审核且足够的参考证据直接给模型，不给标准答案。成功可提示检索或上下文组织问题；仍失败须继续检查任务标签、理解和工具，不能直接认定“必须微调”。诊断结果单列，不纳入正式能力分数。

每轮改进执行以下顺序：

1. 冻结本轮起点，写明要修复的一个主要失败类别、预期收益及判分标准。
2. 保留失败原始输入、可见证据、检索结果、工具回执、模型原始输出和系统最终输出。尚不能确定原因的记录标为待归因。
3. 先核查参考答案与评分是否可靠，再定位资料、解析、检索、适用性、模型理解、工具选择、工具实现、状态或表达问题。
4. 建立一个主要改动的候选，使用同案例的配对比较。若必须同时更改多个组件，增加消融或回滚对照；整包收益不能直接归为训练收益。
5. 先跑受影响任务与必要回归，筛出有效候选后再进行更广的验证和原能力回归。受影响选择规则事先写明，避免只挑获益题。
6. 按“保留、回退、继续调查”作决定，更新失败记录和下一轮假设。

训练候选至少与两条参照比较：冻结的初始基线，以及使用相同当前外围组件的未经本项目微调模型。前者看整个项目进步，后者看训练的净收益。

支持随机种子的组件应登记种子，但种子不等于完全可复现。关键任务预先设定重复运行次数，报告稳定性及失败次数；不能只保留最好一次。不要未经比较就把温度改为0或关闭底模原有推理配置。

## 6. 什么情况下才训练

进入训练实验前应同时具备：模型行为问题在独立开发案例中反复出现；资料及工具路径已核查；经过低成本修正后仍有缺陷；目标可判定；训练用途获准；验证与封存数据分开；可回退模型、预算和非退化指标明确。启动时按项目执行边界确认具体模型、方法、数据、预算和输出位置，本讨论稿本身不构成训练执行授权。

| 已确认的问题 | 优先动作 | 训练条件 |
|---|---|---|
| 缺资料、没有适用参数 | 补充证据或正确表达未知 | 不用训练生成缺失的真实产品事实 |
| 读错表格、漏脚注、单位丢失 | 修复解析和字段记录 | 先保证模型看到的信息正确 |
| 有资料但没检索到、型号筛错 | 修检索、过滤和上下文组织 | 稳定复现后仍有模型行为问题才另行评估 |
| 工具公式或程序结果错误 | 修工具并做独立数值核对 | 不用模型训练掩盖计算错误 |
| 证据充分，仍混淆条件或不能按要求组织判断 | 先试提示及少量示范，再评估监督微调 | 有可审核的正确示范和独立验证目标 |
| 已会完成任务，但稳定存在选答或建议排序问题 | 检查判据，再评估偏好训练 | 专业审阅者能可靠比较优劣，不按语气或篇幅评分 |
| 需要多步策略优化 | 先确认是否有必要，再研究强化学习 | 必须有可验证奖励、可靠模拟环境和明确预算；不以真实危险设备探索 |

SFT、偏好训练和强化学习属于按问题选择的方法，不安排固定串行流程。具体算法、参数高效微调方式、超参数和硬件适配待真实模型、预算和失败分布明确后决定；CPPO等缩写未确定论文和实现前不写入执行方案。

训练样本围绕错误机制设计：正确例子、容易混淆的反例、条件改变后答案应改变的例子，以及未知信息下仍能提供有用分析的例子。混入审核过的原能力保持样本，避免只学会保守措辞或固定模板。不得把本次测试答案复制进去后再以答对原题宣告改善。

## 7. 怎样判断进步、达标和退化

分别报告科学工程正确性、型号与条件匹配、检索和引用支持、数值工具结果、未知与冲突处理、任务完成率、不必要拒绝/追问、时延与资源成本。模型原始输出和系统最终输出分别评分；后端拦住模型错误不能记为模型答对。

严重错误包括：无依据编造操作限值或确定性事故预测；错误型号或条件绑定导致关键结论错误；虚构工具执行、现场批准或检验结果；该展示的紧急升级信息被流程不当延迟；私有案例泄漏。严重程度由预先定义的影响判据和复核确定，不按是否出现某个关键词机械判定。

| 决策项 | 建议规则 |
|---|---|
| 必测覆盖 | 所有本轮必测任务和预定分层都有有效结果。合理未知按预定行为评分；评分依据本身不可靠的题单列，不强算成功或模型失败 |
| 严重错误 | 所选候选在审核后的必测集合及预定重复运行中，严重错误数为0，保留全部结果；总体平均分不能抵消此项。有限测试中未观察到错误不等于现实零风险 |
| 目标收益 | 提前写明最小有实际意义的改善幅度，配对比较及不确定性支持该收益；不能只看单次总分变高 |
| 原能力保持 | 核心物化、工程解释和正常任务完成能力无超过预定容差的退化；误拒绝、追问及成本也有上限 |
| 正式验收 | 冻结一个候选及评分规则后，再使用封存集。未达到上述要求不升级为已验收 |

最小改善幅度、各任务通过线、非退化容差、时延和预算上限需要在正式候选比较前登记。当前缺正式基线、业务优先级和服务器测量，不能有依据地承诺“统一达到95%”或指定训练时长。可在P1获得题目难度及方差信息后确定样本量，但不能根据候选结果反向放宽标准。

比例同时提供正确数/可判定数、总执行数和各分层结果；不把一条曲线上的百万采样点当百万独立案例。同一电芯、来源或案例有依赖时，按独立组计算区间或进行组级重采样。样本太少时如实报告证据不足。候选多次比较、验证集查看次数及选择规则记录在案，防止从大量尝试中挑一个偶然高分。

数值和结构可自动评分；专业关键判断采用匿名输出、独立双评及分歧仲裁。模型评分器先用人工标签校准，只作辅助。现有Sol子代理复核不等同于独立领域专家确认；如果缺少专业审核支持，相关现场结论不能宣称已获专家验收。

## 8. 控制成本与停止条件

优先把预算花在覆盖和可靠判分上。先用确定性程序检查字段、单位和工具结果，再做模型调用；只对进入下一轮的候选扩大评测。确定性证据快照可以复用，真实工具调用与快照回放要分别登记。使用Sol完成有明确标准的整理和初审，总控负责归因和选择；关键专业判断仍需要相应审查。

建议首轮采用以下实验上限作为讨论起点：一个迭代周期聚焦1个主要失败类别，最多比较2个主要候选，选出1个进入更广验证。此数量是成本控制建议，不是统计充分性标准；重复运行和独立案例数量另行设计。预算应包含出题、专业审阅、模型调用、GPU时长、存储和回归，不能只计算训练时间。

| 情况 | 决定 | 状态含义 |
|---|---|---|
| 验收标准全部满足且证据充分 | 停止本轮扩训，冻结可用版本及支持范围 | 仅对本轮声明范围通过 |
| 候选无足够收益，或出现严重错误/超限退化 | 回退到此前通过相应验证的版本，记录失败 | 不采用该候选；当前整体是否通过另行判断 |
| 连续两个周期没有足够收益，或成本超过预定上限 | 停止继续扩训，复查假设、数据和方法 | 研究阶段结束或待调整，不等于产品验收通过 |
| 判据、许可或专业审核依据不足 | 暂不执行受影响部分，继续不依赖该条件的设计工作 | 明确待补项，不填虚构分数 |

发现新需求时，新建范围和版本记录；不要无限扩大同一轮，也不为了满足训练轮数而继续训练。

## 9. 组织与每轮交付

总控负责确定范围、冻结版本、决定保留或回退；案例编制者提供输入及证据；非作者审阅者核查判分卡；执行人员在服务器运行；专业审核者处理关键结论与分歧。至少保持“编题/改模型”与“最终独立验收”职责分离。

每轮只需要一份清楚的报告及其运行证据：本轮问题、输入及版本、实际改动、目标任务结果、原能力回归、成本、严重错误、未覆盖项、保留/回退理由、下一步。保留失败及未运行记录，避免只展示最好答案。

近期可先准备的三项成果是：测试范围表、逐案例判分卡规范、迭代决策与结果记录模板。随后补齐服务器执行条件，在服务器完成基线，再决定是否需要任何训练。该顺序不要求现在预先生产训练样本。
