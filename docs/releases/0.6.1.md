# Battery Inventory 0.6.1

Battery movement summary · 4 October 2026

## Scope

Opening a battery now shows a Check-in / check-out card before its specifications. An active loan displays its holder, checkout time and elapsed duration. An available battery displays the time since its last recorded return and the person who recorded that return. Recent movements show checkout and return operators, exact Sydney timestamps and completed loan durations. Existing full-history views, corrections and exports remain available.

The server resolves the exact active loan, latest effective return and registration actor independently of the 200-row on-screen history limit. Voided checkouts do not contribute to this summary. Reopening a return restores the original active checkout. Elapsed durations use recorded instants, so Sydney daylight-saving changes do not add or remove an hour. Invalid, future or missing timestamps produce an unavailable duration. Removed and scrapped batteries stop current movement tracking.

Registration is never treated as a physical check-in. A battery without a recorded return says No return recorded and shows registration evidence separately. The return operator is not assumed to be the borrower or the person who physically brought the battery. Recorded loan state does not establish continuous physical location. Per-battery safety-test records are outside this change.

## Data and release boundary

This update adds a read-only detail projection and UI component. It does not change write permissions, account credentials, database tables or any of the 16 applied migration files. The frozen 0.6.0 branch and tag remain unchanged. Source publication excludes credentials, business databases, generated builds and local deployment artifacts.

## Verification

The implementation passed **450 isolated tests**, including 11 movement-summary cases using actual D1 semantics, **100 production-Worker HTTP checks**, TypeScript, full ESLint and the production build. The HTTP suite checks that the detail summary retains the original registration, checkout and return actors. Browser inspection covered active loans, completed returns and missing return history at desktop and 390 x 844 sizes, with no browser warnings or errors observed. These checks used an isolated database with fictional accounts.

Existing large-chunk and build-plugin timing warnings remain. Full accessibility compliance, load capacity and hardware location sensing are not established by these checks. Hosted upgrade verification is recorded separately after deployment.
