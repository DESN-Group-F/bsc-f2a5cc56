## Frozen scope

Staff and Administrator interfaces now reflect the consolidated [permission baseline](../permissions.md). Staff retain operational and personal workspaces with read-only shared directories. Administrator maintenance and account tools appear under Administration. My activity shows current In store / In use status alongside historical operations and offers reviewed checkout and return actions. Server-side role, account, loan and version checks remain authoritative.

Task creation offers a blank Custom task alongside optional prepared templates. The editor exposes task content, targets, schedules, assignment and state choices; saved plans have explicit viewing and editing actions. Prepared templates can be converted to custom plans without discarding entered configuration. Existing cycles, recorded deadlines, removal history and exact-request recovery are retained.

Excel downloads start with an explanatory Report guide and readable business worksheets, including names, units and Sydney timestamps. Initially hidden Evidence worksheets retain original fields and full records. CSV headings are readable, and JSON remains structured evidence. Inventory, activity, directories, tasks, personal Messages and administrator account downloads retain their existing scope and authority; credentials and sessions are excluded.

Battery selection uses shared filters across Activity, movement dialogs, scan selection and completion, teaching groups, task targets, downloads, removal and registered intake results. Clear filters retains chosen records and fixed operation boundaries. Clicking noninteractive row content selects the battery; embedded actions and keyboard-accessible checkboxes retain their own behavior. Pending review queues remain fully visible.

Scan checkout and Scan return use one workflow for 1–100 batteries: add tags or manual selections, review the queue, then explicitly confirm. The Continuous / Batch selector and immediate-save path are removed. Confirmation leaves the station open. Interrupted older requests retain their exact payload and request ID; retrying them does not automatically submit the remaining queue. First-time registration keeps its separate editable intake drafts and confirmation.

The existing movement summary, yellow-and-ink design, shared inventories, personal teaching groups, recoverable task removal and complete historical evidence remain available.

## Validation

The isolated release source snapshot passed **527 tests, zero failures and zero skipped tests**, full ESLint, TypeScript and the production build. A fresh production Worker with all **17 migrations** passed **102 HTTP checks**. The release snapshot excludes the diagnostic NFC route and tests. Dependency declarations and resolved lock entries are unchanged; only the root package versions advance to 0.7.0.

Browser checks during development verified role-specific navigation, custom task creation/editing, readable download controls, shared filters and row selection. The final scan change was exercised with two queued returns and one manually selected checkout: authenticated database inspection confirmed that staging did not change loans and explicit confirmation did. The station stayed open. Those dated checks are not represented as a new complete browser walkthrough of every feature during the freeze.

Earlier local D1 transport failures and the successful standalone rerun remain in the dated [validation record](../validation.md). The release snapshot's complete test run passed without such a failure; this does not establish the cause of the earlier intermittent connection errors. Existing large-client-chunk/performance build advisories remain.

## Migration and deployment boundary

An installation at 0.6.1 needs the new `0016_custom_task_plans` migration. Preserve a database backup and apply only unapplied migrations in journal order. The migration expands permitted task categories and retains prior rows, identity checks, triggers and historical references. None of the 16 previously applied migration files is changed by this release. Local migration verification compared all existing business rows before and after the change; detailed evidence is recorded in validation.

This milestone publishes source only. It does not restart or upgrade OpenBayes, apply a hosted migration, change account credentials or copy local business data. The currently hosted 0.6.1 service remains separate from this frozen source.

## Exclusions and limits

The separately approved mobile/NFC functional-test prototype, its diagnostic web route, native projects and cloud build configuration are excluded from this formal release. Its local development files are preserved. Real RFID ingestion, verified room mapping, school SSO, external procurement integration, email delivery and unattended reminders remain outside the supported release.

The freeze excludes installed dependencies, generated builds, local credentials, sessions, business databases and private test artifacts. The required `.openai/hosting.json` platform adapter metadata, authentication protocol identifiers and third-party license notices are retained for their technical and legal functions; they are not product branding.

The permission baseline records existing limits, including shared visibility of personal-message action metadata and role-downgrade effects on administrator-only exact-request recovery. This source freeze does not claim to resolve those limits or establish hardware acceptance, full accessibility compliance, load capacity or measured staff time savings.
