# Staff workflow demonstration and guide

This guide shows four local prototype workflows that reduce repeated entry and coordination for teaching staff: batch borrowing and returns, shared tasks, selections across pages, and reusable periodic task templates. It contains a presentation script and a short guide for everyday use. All demonstrations use fictional records in **Demonstration inventory**.

| Workflow | What the presenter should show | Work avoided |
| --- | --- | --- |
| Batch borrowing and returns | Two batteries in one reviewed transaction, with the signed-in borrower supplied automatically | Separate forms and repeated borrower entry |
| Shared tasks | One teacher completes a cycle and another teacher sees it completed | Recording the same shared task twice |
| Selections across pages | A chosen set survives page changes, search and Clear filters | Finding and selecting the same batteries again |
| Periodic task templates | Supplied task content and recurrence, with a shortcut for assigning responsible owners | Designing the basic workflow and repeatedly entering staff names |

## Prepare the demonstration

Use one administrator and two active staff accounts, referred to here as Teacher A and Teacher B. Use their actual account usernames when selecting assignments; matching display names do not establish identity. Sign in with accounts supplied by the administrator. Do not include passwords in slides or handouts.

Prepare these fictional records in a demonstration environment:

- Enough registered batteries to span two result pages. For example, use more than ten batteries and choose ten per page.
- Two batteries registered to the same demonstration storage area, one assigned to each teacher as responsible owner, for the shared area task.
- Two available batteries for Teacher A to borrow and return as a group.
- A clearly labelled demonstration task whose reminder date and Sydney time have already passed, for the shared inbox scene.

Use existing records where they meet these conditions. Completed cycles and returned loans remain history; prepare a new fictional cycle or loan when repeating a scene. Do not reset existing transaction history to reproduce an earlier screen.

For a connected walkthrough, run the scenes in this order: **Periodic task template → Shared task → Selection across pages → Batch borrowing and returns**. The script below names the controls shown in the current local application. Example plans and dates are demonstration settings, not verified operating or safety requirements.

## Scene 1 Prepare a periodic task from a template

**Role:** Administrator. **Goal:** Prepare one reusable plan covering the relevant assets and staff.

1. Open **Recurring tasks**. Under **Weekly storage-area review**, select **Use template**.
2. Review the supplied task title, work and management basis. Give the plan a title that clearly identifies it as a demonstration.
3. Choose the demonstration storage area and enter its fictional scope in **Scope and applicability**. A labelled placeholder area is allowed only for this demonstration configuration.
4. Select **Use responsible owners**. Review the resulting account assignments and confirm Teacher A and Teacher B are included.
5. Set an explicit first due date and an unambiguous **Australia/Sydney** reminder time. For the next scene, use a reminder that has already passed. Leave the supplied recurrence unchanged to show the template default.
6. Review the schedule preview. Choose **Active · generate Messages while in use**, tick **Confirm the plan before activation**, and select **Create task plan**.
7. Show the saved plan, assignments, recorded open cycle and due date.

**Presenter line:** “We configure this review once for the area and its responsible staff. The template supplies the starting content and recurrence, and the owner shortcut fills existing accounts.”

The other templates are **Teaching-period inventory reconciliation** and **Six-month storage maintenance review**. The reconciliation template uses explicitly entered teaching-period dates. Administrators must confirm actual applicability, targets, dates and assignments before activating any real plan. **Use responsible owners** fills the current assignments when selected; it does not continuously reassign a saved plan after ownership changes.

## Scene 2 Complete a shared task once

**Roles:** Teacher A and Teacher B. **Goal:** Show that one actual completion closes a shared cycle for everyone assigned to it.

1. Teacher A opens **Messages** and selects **Refresh messages**. Show the demonstration task under **To do**.
2. Teacher B also opens **Messages** and selects **Refresh messages**. Show their personal message for the same shared cycle.
3. As an optional explanation, Teacher A selects **Mark read**. Show that the task remains **To do** and Teacher B's message remains **Unread**. Reading is separate from doing the work.
4. Teacher A selects **Open task** and reviews the recorded requirements and affected assets. Perform the fictional review before recording its completion.
5. Leave **Completion notes (optional)** blank to show that routine completion does not require a report. Tick **I have completed this task.** and select **Record completion**.
6. Teacher B selects **Refresh messages** and opens **Completed**. Show the shared completion, including its recorded actor and time, without entering another completion.
7. Open **To do** for Teacher B and show that this completed cycle is absent. Their old message may still be **Unread** until they read it.

**Presenter line:** “Two teachers can receive the same shared requirement. Once one teacher performs and records it, the group does not have to repeat the completion entry.”

If the message is absent, check the plan is active, both accounts are assigned, its reminder time has passed, and the same inventory is selected. Use **Refresh messages** and **Clear filters** before concluding that no message exists. Opening or reading a task does not record completion.

## Scene 3 Keep a selection across pages and searches

**Role:** Either teacher. **Goal:** Assemble one chosen equipment set across several result pages.

1. Open **Battery inventory** and select one known battery on the first page.
2. Select **Next** and choose a second battery. Point out that the selected total includes both pages.
3. Open **Filter** and search for a term that shows only one of those batteries. Show that the other chosen battery remains selected outside the current filters.
4. Select **Clear filters**. Show the full results and the same two selected batteries.
5. Select **Download selected**. In the review, show **Selected batteries (2)** and the explanation that the selection includes batteries across pages and filters.
6. Select **Cancel** if no file is needed for the demonstration. Use **Clear selection** before starting an unrelated scene.

**Presenter line:** “Searching changes what we can see. It does not make us rebuild the equipment set we already chose.”

**Clear filters** resets the criteria and page while preserving chosen records and the current inventory or personal view. **Clear selection** removes chosen records. The checkbox labelled **Select all batteries on this page** selects that page; it does not select every filtered result on every page.

## Scene 4 Borrow and return batteries as a group

**Role:** Teacher A. **Goal:** Borrow two batteries for teaching, then return both with one confirmation.

1. Open **Battery inventory → In store** and select the two prepared batteries.
2. Select **Check out selected**. Show the two-row review and the signed-in staff account under **Checked out to**. There is no substitute borrower to enter.
3. Select **Confirm checkout (2)**. Wait for the saved result before describing the batteries as borrowed.
4. Open **My loans**. Select the two loans; use **Select all batteries on this page** only if this page contains exactly the intended return set.
5. Select **Return selected**. Review the two batteries and their current holders, then select **Confirm return (2)**.
6. Show that these two loans are gone from **My loans** and their battery details retain the returned loan history. The count becomes zero only if these were Teacher A's only outstanding loans.
7. Use **Clear selection** if completed IDs remain selected outside the personal view.

**Presenter line:** “Two returns share one confirmation. The system already knows the signed-in borrower and retains who performed each operation.”

Responsible ownership and current borrowing are separate. Returning a battery does not change its responsible owner or registered storage home. A teacher may receive another staff member's battery through the shared inventory. A single checkout or return supports up to **100 batteries**; review the entire intended set before confirming.

## Daily staff quick guide

| Need | Short route |
| --- | --- |
| Borrow several available batteries | **In store → select rows → Check out selected → review → Confirm checkout** |
| Return your own current loans | **My loans → select rows → Return selected → review → Confirm return** |
| Find the batteries you are responsible for | **My batteries**; this can include batteries currently borrowed by someone else |
| Resume searching without losing your chosen set | **Clear filters** |
| Start a new selection | **Clear selection** |
| Find outstanding assigned work | **Messages → To do**; reading a message alone does not complete it |
| Record completed assigned work | **Open task → review and perform the work → confirm completion → Record completion**; notes are optional |
| Prepare another periodic plan | Administrator opens **Recurring tasks → Use template**, reviews its scope and assignments, and confirms its schedule |

If an operation reports an uncertain result, use its offered original-request retry and wait for confirmation. If it reports changed records, review the current records before accepting a new draft. Do not repeat the operation as though the earlier request never existed.

## What the demonstration establishes

Independent fictional scenarios verified the two-loan batch return, shared completion with separate personal read state, cross-page selection through searching and clearing filters, and creation of a weekly plan from a supplied template. See the [validation record](validation.md) for actual verification scope.

Messages are generated during authenticated use once the configured reminder time has passed. Email and unattended scheduling are unavailable. This demonstration does not require an RFID reader, establish physical location, or certify battery safety. Catalog and RFID integration are deferred from this demonstration scope.

These workflows remove specific repeated entries and completion steps. No real-teacher elapsed-time study or percentage efficiency gain has been measured. The selection scene verifies download scope in the review dialog; actual desktop file saving was not independently verified in the previous in-app browser review.
