# Battery Inventory App functional test source

This standalone snapshot contains **Test 0.5.2**, an internal functional-test application excluded from formal product releases. It does not change the main application's release version. It includes the bundled existing inventory frontend, mobile business adapters and both native plugins. No Git history, backend, business database, installed dependency tree or signed application is included.

## Included workflows

The frontend retains account sign-in, inventory/status/filter/detail/history views, reviewed manual checkout and return, models, teaching groups, tasks, messages, complete-history exports and existing role-controlled administration. New mobile registration is demonstration-only, supports canonical NFC identifiers or untagged manual entry, and preserves an exact request before sending. Checkout and return require explicit review and confirmation; reading a tag stages its identity and never creates a battery or commits a movement automatically.

The native service adapter provides configured HTTPS authentication, protected session storage, durable business recovery and file-export handoff. Browser preview uses same-origin sessions and reports native NFC unavailable. Physical NFC evidence, manually entered identities and controlled adapter tests remain separate; no tracking or real RFID ingestion is enabled.

## Local preparation

Use Node.js 22.13 or newer. From this snapshot directory:

```powershell
cd mobile
npm ci
npm test
npm run test:plugin
npm run build
node ../scripts/prepare-mobile-native.mjs --all
npm run dev
```

The build helper verifies the bundled frontend when the original main application sources are absent. The native projects are included, but web assets and native plugin metadata must be regenerated by build and sync. A web build or project check does not prove native compilation, signing, installation or NFC operation. Android control-flow tests require a JDK and explicitly skip if it is unavailable.

Business operations require a separately prepared, authorized backend containing the matching mobile registration contract and existing inventory APIs. Native connections require an HTTPS origin; browser sessions require a same-origin backend route. The backend and isolated local preview launcher are not included. Running the interface alone does not start the backend, and existing hosted endpoints are not assumed to support this test version. Configure an authorized test environment before entering business data.

The active `codemagic.yaml` contains three manually started workflows: unsigned iOS verification, Android debug packaging and a signed iOS TestFlight package. The signed workflow uses the configured protected Apple integration and NFC App Store profile and uploads to App Store Connect for the owner's internal testing. Automatic external beta review, public App Store submission and automatic build triggers remain disabled. All script steps stop on failed commands. An unsigned iOS artifact cannot be installed on an iPhone. The separate `templates/testflight-workflow.yaml` retains the reference definition. This source prepares an internal test package; physical iPhone validation remains separate.
