## Frozen behavior

The redesigned sign-in and inventory workspace use the blue-and-white visual system, shared control sizes, clearer navigation and responsive layouts. Dialogs preserve explicit navigation choices and restore a usable opener after nested or responsive transitions. Shared motion responds to reduced-motion changes without tying business outcomes to animation completion.

The Review queue starts closed. At a workbench width of at least 1100px, it opens a real 280px column aligned with the records top; closed state leaves a compact 52px entry. Smaller workbenches use a modal drawer. At narrow viewport widths the entry is a horizontal row above full-width records. Selection, filters, pagination, totals and business drafts remain independent of the presentation container. Queue opening does not commit an operation or bypass an existing review or recovery guard.

All existing business features remain: shared inventories, native staff authority, reviewed checkout/return, private Teaching groups and temporary alternatives, complete evidence exports, model-assisted registration, inspection and usage records, guarded retirement/recovery/deletion and new-registration reminders. API sources, database migrations and dependency declarations are unchanged from 0.8.0.

## Validation

The immutable frontend source parent passed 79 tests across seven relevant suites, with zero failures or skipped tests, TypeScript checking, full ESLint and a production build in an isolated publication snapshot. Separate scoped audit evidence includes 54 affected business cases at the unchanged table snapshot, 31 shared-focus checks and a nine-case retained-pane model. These overlap and are not a combined coverage total.

Independent browser checks confirmed top-aligned queue geometry, compact closed state, preserved selections/totals, return to the original battery button after detail/resize/close, visible reverse-Tab targets and valid focus after immediate drawer reopening. Recorded browser warnings and errors were empty. Earlier failing candidates and probe limitations remain in the [functional audit](../frontend-refactor-functional-audit.md), [visual audit](../frontend-refactor-visual-audit.md) and [implementation record](../frontend-refactor-implementation.md).

The 0.9.0 follow-up changes only root version metadata and release documentation from that tested parent. Dependency comparison permits only the package version and the two lockfile root version fields; the complete resolved graph is unchanged. A fresh production build validates the versioned source. The existing large-client-chunk warning remains. No new full domain or HTTP regression run is claimed for this metadata-only follow-up.

Complete browser/accessibility coverage, animation frame stability, loading-performance gains, measured staff efficiency, physical NFC and native-device acceptance remain outside these results.
