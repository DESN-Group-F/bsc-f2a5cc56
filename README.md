# Battery Inventory NFC scan trial source

This standalone snapshot contains **Test 0.2.0**, an internal functional-test application excluded from formal product releases. It does not change the main application's release version. It includes the bundled existing inventory frontend, mobile business adapters and both native plugins. No Git history, backend, business database, installed dependency tree or signed application is included.

The immediate trial is native NFC proposal, demonstration asset binding, reviewed checkout and return. The App design remains deferred. This candidate retains the vetted 5 October Test 0.2 frontend instead of copying later main-application work. On 8 October, the operator initially reported active Apple membership and App Store Connect not yet enabled, but the authenticated Apple account page later showed pending membership and a purchase/processing notice. Certificates, Identifiers & Profiles also denied team access. The operator subsequently confirmed that this is the Apple account used for the approved application. Paid team activation and the exact billing or provisioning cause remain unresolved; both signing routes are blocked for that observed account. The current trial guide records this confirmed account identity and the latest readiness checkpoint. Codemagic Personal was signed in with no signing certificates listed. See the current trial guide for the dated checkpoint and separate local checks.

## Included workflows

The frontend retains account sign-in, inventory/status/filter/detail/history views, reviewed manual checkout and return, models, teaching groups, tasks, messages, complete-history exports and existing role-controlled administration. New mobile registration is demonstration-only, supports canonical NFC identifiers or untagged manual entry, and preserves an exact request before sending. Checkout and return require explicit review and confirmation; reading a tag stages its identity and never creates a battery or commits a movement automatically.

The native service adapter provides configured HTTPS authentication, protected session storage, durable business recovery and file-export handoff. Browser preview uses same-origin sessions and reports native NFC unavailable. Physical NFC evidence, manually entered identities and controlled adapter tests remain separate; no tracking or real RFID ingestion is enabled.

## Local preparation

Use Node.js 22.13 or newer. From this snapshot directory:

```powershell
cd mobile
npm ci
npm test
npm run test:plugin
npm run build
node ../scripts/prepare-mobile-native.mjs --all
npm run dev
```

The build helper verifies the bundled frontend when the original main application sources are absent. The native projects are included, but web assets and native plugin metadata must be regenerated by build and sync. A web build or project check does not prove native compilation, signing, installation or NFC operation. Android control-flow tests require a JDK and explicitly skip if it is unavailable.

Business operations require a separately prepared, authorized backend containing the matching mobile registration contract and existing inventory APIs. Native connections require an HTTPS origin; browser sessions require a same-origin backend route. The backend and isolated local preview launcher are not included. Running the interface alone does not start the backend, and existing hosted endpoints are not assumed to support this test version. Configure an authorized test environment before entering business data.

The candidate `codemagic.yaml` contains four manual workflows: unsigned iOS verification, Android debug packaging, registered-device Ad Hoc packaging, and internal-only App Store Connect upload. No cloud run or upload has occurred by preparing this source. The Ad Hoc workflow needs a registered iPhone UDID and matching protected certificate/profile, but no App Store Connect integration. The internal workflow uses the protected `battery-inventory` integration, requires a matching App Store profile/app record, and sets both review-submission flags to false. Existing Apple internal-group automatic distribution must still be checked. The separate template is a reference copy of that workflow. All signing inputs and the provisional `com.batteryinventory.mobile` ownership remain unconfirmed. Repository publication, account actions, cloud builds, uploads and installation are separate checkpoints.
